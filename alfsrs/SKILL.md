# /alfsrs — 制记忆卡

素材来自**当前会话上下文**：本次讲解中出现的高记忆价值内容 + 本次批改暴露的知识缺口。

**首要原则：能推导的不制卡。** 凡是给足时间能从更基本的原理现场推出来的东西（比如由定义直接推出的性质、由公式直接展开的推论），制卡只会制造垃圾复习负担。只有"无法现场推导、必须准确回忆"的才值得做卡：约定与记号（人为规定的符号、边界条件的具体形式）、经验结论与对照表（需要逐项记住的分类结论）、公式定理的准确形式（漏一项就错的那种）、易混概念的辨析边界。自检问题："给足时间，能否从更基本的原理推出？" 能 → 不制卡。

卡面针对知识缺口本身，不要把题干搬上去（题已进错题 FSRS）。

流程：

1. 回顾会话，列出候选卡清单给用户过目：每张卡给出 Q/A 草稿和出处（模块号或题号）。
2. 用户确认/删改后，写入 `.al/<course>/anki_cards/<模块号>.md`（追加，已存在则增量更新）。卡格式：

```markdown
<!-- id: k2.2.01 | tags: 标签1 标签2 -->
Q: 问题（一问一个点）
A: 答案（不超过三行；
   需要辨析的写清边界）
```

- 一卡一个点，答案不超过三行；卡 ID 稳定（`k<模块号>.<序号>`，如 `k2.2.01`），重写卡片用同 ID 覆盖。
- md 文件是事实来源，Anki 只是镜像。
3. 同步：写盘后运行 `uvx python <本 skill 目录>/scripts/anki_sync.py`（路径解析规则见 `../al/reference/PROTOCOL.md` 开头「脚本路径约定」；经 AnkiConnect 增量推送：按 CardID 匹配，新增/更新 note，牌组 = 课程名）。若连接失败（Anki 未开或 AnkiConnect 未装），如实告知用户；备胎是用 genanki 导出 apkg 到 `.al/<course>/dist/`。md 里删掉的卡不会自动从 Anki 删除，脚本只报告孤立卡，需删除时征求用户同意。
4. 纪律：若会话已经历过 compact，上下文细节可能已稀释——此时如实告诉用户只能基于可见上下文制卡，不要编造"会话里讲过"的内容。
